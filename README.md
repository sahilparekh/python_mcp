# FastMCP Python Code Executor

A FastMCP (Model Context Protocol) server that executes Python code in an isolated environment with strict library controls and uploads generated artifacts to Google Cloud Storage.

## Core Functionality

- **Code Execution**: Executes user-provided Python code.
- **Library Validation**: Enforces a strict list of allowed Python libraries for security and stability.
- **Artifact Management**: Automatically uploads any files generated by the executed code to a configured Google Cloud Storage (GCS) bucket.
- **Isolated Environments**: Uses temporary directories for each execution run.
- **Timeout Protection**: Code execution is limited to a 60-second timeout.

## Setup

### 1. Install Dependencies

Ensure you have Python 3.8+ installed. Then, install the required packages:

```bash
pip install -r requirements.txt
```

### 2. Configure Google Cloud Storage (GCS)

This server requires a GCS bucket to store artifacts generated by the Python code.

1.  **Create or identify a GCS bucket** in your Google Cloud Project.
2.  **Update `GCS_BUCKET_NAME`**: In `utils.py`, change the `GCS_BUCKET_NAME` variable to your actual bucket name:
    ```python
    GCS_BUCKET_NAME = "your-actual-gcs-bucket-name"
    ```
3.  **Authentication**: Ensure your environment is authenticated to access GCS. The server uses Google Cloud client libraries, which support various authentication methods (e.g., service account key file via `GOOGLE_APPLICATION_CREDENTIALS`, or Application Default Credentials if running on GCP infrastructure).
    For local development, you can use:
    ```bash
    gcloud auth application-default login
    ```

### 3. Run the Server

You can run the FastMCP server using an ASGI server like Uvicorn:

```bash
# Make sure GCS_BUCKET_NAME is configured in utils.py first!
export GCS_BUCKET_NAME="your-actual-gcs-bucket-name" # Or set it directly in the file
uvicorn utils:mcp.app --reload --port 8000
```

Replace `your-actual-gcs-bucket-name` with your bucket name if using the environment variable method.

## Available MCP Components

### Tool: `execute_python_code`

Executes the provided Python code string.

**Request Parameters:**

*   `code` (string, required): The Python code to execute.

**Response Body (JSON):**

*   `stdout` (string): The standard output (and standard error) from the code execution.
*   `artifacts` (list of strings): A list of GCS URIs for any files generated and uploaded from the execution.
*   `validation` (object): Contains results from the library import validation:
    *   `is_valid` (boolean): Whether all imported libraries are allowed.
    *   `validation_message` (string): A summary message.
    *   `allowed_imports_found` (list): List of detected imports that are allowed.
    *   `disallowed_imports_found` (list): List of detected imports that are *not* allowed.
*   `execution_status` (string): Indicates the outcome (e.g., "completed", "aborted (validation)", "error (timeout)", "error (setup)", "error (unknown)").

**Example MCP Client Call (Conceptual Python):**

```python
# Assuming 'client' is an initialized MCP client
code_to_run = "import pandas as pd\ndf = pd.DataFrame([{'a': 1, 'b': 2}])\nprint(df.to_string())\ndf.to_csv('output.csv')"

response = await client.call_tool(
    "execute_python_code", 
    {"code": code_to_run}
)

print(f"Output:\n{response['stdout']}")
if response['artifacts']:
    print(f"Artifacts: {response['artifacts']}")
else:
    print("No artifacts produced or GCS_BUCKET_NAME not configured.")

print(f"Validation: {response['validation']}")
print(f"Status: {response['execution_status']}")
```

### Resource: `docs://allowed-libraries-versions`

Provides documentation on the Python libraries that are permitted for execution by the `execute_python_code` tool, including their versions as specified in `requirements.txt`.

**How to Access:**

MCP clients can request this resource by its URI.

**Content (Markdown):**

The resource returns a Markdown document listing:
*   Allowed third-party libraries (e.g., pandas, seaborn, matplotlib).
*   Their versions, as read from the server's `requirements.txt` file.
*   A note that all Python Standard Library modules are also permitted.

**Example MCP Client Call (Conceptual Python):**

```python
# Assuming 'client' is an initialized MCP client
allowed_libs_docs = await client.get_resource("docs://allowed-libraries-versions")
print(allowed_libs_docs) # This will be a Markdown string
```

## Library Restrictions & Security

*   **Strict Validation**: Before any code is run, it is scanned for `import` statements. Only libraries explicitly listed as allowed (see `docs://allowed-libraries-versions` and Python Standard Library) can be imported.
*   **Purpose**: This restriction is crucial for:
    *   **Security**: Preventing the execution of arbitrary, potentially harmful code that could access unintended system resources or network locations.
    *   **Stability & Consistency**: Ensuring the execution environment is predictable and uses tested library versions.
    *   **Resource Management**: Avoiding uncontrolled consumption of resources by unknown libraries.
*   **Failure Mode**: If disallowed imports are detected, the `execute_python_code` tool will abort before execution and return a validation error, detailing the problematic imports.

## Development Notes

*   **`GCS_BUCKET_NAME`**: This is a critical configuration. If not set or set to the placeholder `"YOUR_BUCKET_NAME"`, artifact uploads will be skipped, and a warning will be included in the `stdout`.
*   **Error Handling**: The `execute_python_code` tool attempts to catch various errors, including timeouts, Python interpreter issues, and general exceptions during code execution or artifact upload.
*   **`requirements.txt`**: This file is the source of truth for the versions of third-party libraries. The `docs://allowed-libraries-versions` resource reads this file to provide version information.
